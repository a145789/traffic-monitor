# Agent Note：升级不再复活被用户关闭的开机自启

Status: implemented

## 问题

开机自启的 Run 值有两个写方：安装器的 `[Registry]` 条目（`installer.iss:44`，写 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\TrafficMonitor`，受 `:41` 的 `startup` 任务控制）与应用的托盘开关（读 `src/tray.rs:277-278`、删 `:282`、写 `:283-290`；路径常量 `src/config.rs:50`，菜单 ID `src/config.rs:224`，分发 `src/tray.rs:266`）。Inno 默认开启 `UsePreviousTasks`（官方：Setup 启动时查注册表判断同一应用是否已安装，是则用上次安装的任务勾选状态作为本次默认），于是：用户在托盘里关掉开机自启（值被删除）→ 下次升级向导里 `startup` 勾选框按记忆仍是勾选 → 用户照常点完向导 → Run 值被重新写回。**用户显式关闭的设置被升级悄悄复活**，对关掉自启的用户每次升级都复现；自动更新走 `/VERYSILENT`（`src/update/installer.rs:611`），静默升级同样按记忆处理任务，复活发生在无人看到的路径上。

附带背景（不在本次范围）：该值由提权安装器写 `HKCU`，在「标准用户 + 管理员凭据」场景会落到提权账户的 hive（`installer.iss:21-23` 已用 `UsedUserAreasWarning=no` 抑制 IS 警告并注明知情取舍）。

## 提案

给 `startup` 任务加 `checkedonce` flag（`installer.iss:41` 一行改动）：

```ini
Name: "startup"; Description: "开机自动启动"; GroupDescription: "启动选项:"; Flags: checkedonce
```

官方语义（[Tasks] 的 Flags）：`checkedonce` 让该任务在「检测到已安装同一应用」时**初始为不勾选**；全新安装不受影响，仍按默认勾选。效果：

- 全新安装：勾选框默认勾选，行为与今天完全一致；
- 托盘关掉自启后升级：勾选框从「不勾」起步，用户不动它 → `[Registry]` 条目（`Tasks: startup`）不处理 → Run 值保持为空，不再复活；
- 升级时想重新启用：勾选框勾上 → 照常写入（显式动作，不是复活）；
- 自启当前为开的用户升级：勾选框初始不勾、不动它 → 不写入，既有 Run 值原样保留，自启不受影响。

一行 flag 同时修好交互与静默两条升级路径，不新增 `[Code]`、不新增注册表值、不损失首装勾选框。

## 明确不在本次范围

- 不修「标准用户 + 管理员凭据时写错 hive」（`installer.iss:21-23` 既有知情取舍）：可靠路径是应用自己的托盘开关（运行在正确用户下）。
- 不动 `UsePreviousTasks` 本身：全局关掉会让其它任务也丢记忆，且 `checkedonce` 已按任务粒度解决本问题。
- 不动安装器的优雅退出/强杀链与完成判定（`installer.iss:102-165`）。
- 不改「升级时取消勾选并不会删掉既有 Run 值」这一既有语义（今天也如此）：安装器勾选框只负责「写入」，关闭自启的唯一入口是托盘开关；把「取消勾选」改成「删值」会引入第二个删除方，另议。

## 为什么不保留？

1. 「两个属主各管一段，不冲突。」—— 它们写的是同一个值的两个方向（写/删），且安装器按记忆状态重新写；「升级复活用户显式关闭的设置」正是本篇要消除的可感知行为。
2. 「给 `[Registry]` 条目加 `Check:` 守卫、只在全新安装写。」—— 也能消除复活，但升级向导里勾选框仍按记忆显示勾选（与实况相反），且用户升级时想重新启用会被守卫静默拦下；`checkedonce` 让勾选框从实况出发、勾选即写入，语义一致且只有一个 flag。
3. 「改写成『意图值』、由应用收敛真值。」—— 权限范围打架：标准用户用管理员凭据安装时安装器写进管理员账户的 hive，应用读不到；要修就得写机器级 HKLM，而托盘开关是普通用户权限。为修一个复活 bug 不值得。
4. 「删掉安装器勾选框、自启只由托盘管。」—— 属主最干净，也是 Inno 官方对 admin 模式的指引方向（user-level 设置应由应用自理）；但这是任务栏常驻组件，装完重启发现组件不在会被当成「装坏了」，为少一个属主牺牲首装体验不划算。
5. 「这是 Inno 默认行为，别改。」—— `UsePreviousTasks` 的记忆在这里与「托盘开关是自启的唯一运行时属主」冲突；`checkedonce` 是官方 flag，一行修复、不引入自造判据。

## 验收标准

- `grep -n "checkedonce" installer.iss` 命中 1 处，且位于 `startup` 任务行。
- 真机三例：①全新安装保持勾选「开机自动启动」→ Run 值写入，重启后组件自动出现；②托盘关掉自启 → 升级（勾选框初始不勾、不动它）→ Run 值仍为空；③自启为开 → 升级（不动勾选框）→ Run 值仍在，组件升级后正常自启。
- 四条门禁全绿（本项不改 Rust 代码）；`installer.iss` 的改动需在真有 ISCC 的环境编译通过（本机无 ISCC，是已知验证缺口）。

## 风险

- `checkedonce` 依赖 Inno 的「同一应用」判定（AppId + 安装模式 + 位数，官方 same-application 规则）：本仓未设 `AppId`，缺省取 `AppName`（`installer.iss:2`），卸载键即 `...\Uninstall\Traffic Monitor_is1`；AppId 稳定，判定失效的面很小，但若未来有人改 `AppName`/安装模式，复活行为会回来——验收②钉住。
- 升级时勾选框初始不勾，即使自启当前为开：外观上与实况不符，但语义是「本次安装是否（重）写 Run 值」，不动它就不会改任何东西；若用户勾上，写入的是相同内容，无副作用。
- 本机无 ISCC，无法编译验证；由 release 工作流首次编译验证。
