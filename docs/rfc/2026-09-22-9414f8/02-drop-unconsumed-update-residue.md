# Agent Note：清理 update 模块四处无消费者表示（动作 memo、弃用返回值、死归一化、多余 derive）

Status: proposed

## 问题
`src/update/` 下四处「表示存在但没有读者、或被更强契约覆盖」的表面积。(a) 子进程协议扫描的「首个动作」memo：`src/update/protocol.rs:126` 的 `action: Option<UpdateAction>` 只记首个有效动作（写入逻辑 `src/update/protocol.rs:157-158` 的 `if parsed_action.is_none() { parsed_action = Some(action); }`），而它唯一的生产消费 `src/update/protocol.rs:114` 只读 `.is_none()`（等价于「是否出现过有效行」），Done 与 ExitMain 的**值**没有任何生产读者——读到 EXIT_MAIN 时的转发判定（`src/update/protocol.rs:160`）用的是当行解析出的局部变量，不读 memo。(b) `wait_main_instance_gone() -> bool` 的返回值无消费者：定义 `src/update/installer.rs:182`、两个返回点 `src/update/installer.rs:196` 与 `:215`，唯一调用 `src/update/mod.rs:354` 直接丢弃。(c) 三处 `to_uppercase()` 死归一化：`src/update/installer.rs:70`、`:136`、`:162` 对已是大写的哈希再转大写——比对左侧由 `src/update/crypto.rs:122-126` 的 `format_hex`（`{b:02X}`）保证大写，右侧 `expected_hash_hex` 源自 `src/update/version.rs:68` 的 `hash_line.to_ascii_uppercase()`，两份契约各有测试钉死（`src/update/crypto.rs:136` 的 `test_format_hex`、`src/update/version.rs:133` 的 `test_parse_update_metadata_lowercases_hash_to_upper`）。(d) `Version` 的多余 derive：`src/update/version.rs:5` 的 `Clone, Copy, Eq, Ord` 无消费（比较只用 `>` 即 `PartialOrd`，断言只需 `PartialEq + Debug`）。检索记录：内置 grep `parsed_action|action: Option<UpdateAction>|test_scan_memo|is_error: read_failed`（`src/update/protocol.rs`）命中 8 行、值级消费 0；`wait_main_instance_gone`（`src/`）命中定义 1、use 1（`src/update/mod.rs:43`）、调用 1（`src/update/mod.rs:354`）；`to_uppercase`（`src/update/`）命中 `installer.rs:70/136/162` 三处；`derive(Clone`（`src/update/version.rs`）命中 1 行。

## 提案
主项 (a)：`ScanOutcome.action` 改为 `saw_valid_action: bool`——删 `src/update/protocol.rs:157-159` 的条件 memo（parse 命中处置位 `true` 即可），删字段文档「扫描到的首个有效动作」（`src/update/protocol.rs:125-126`），`src/update/protocol.rs:91`、`:176` 的构造与 `:114` 的 `is_error` 判定改读 bool；删整条 `test_scan_memo_keeps_first_action_but_still_forwards`（`src/update/protocol.rs:354-360`）——它的「转发恰好一次」半边已由 `test_scan_duplicate_exit_main_forward_only_once`（`src/update/protocol.rs:306`）覆盖，「保留首个」半边不承重（测试注释 `src/update/protocol.rs:355` 自证「is_error 判定只消费 is_none」）；测试 helper `scan` 的五元组返回（`src/update/protocol.rs:269`）随之把首元素从 `Option<UpdateAction>` 换成 `bool`（元素个数不变，仍是 5 个）。净删约 15 行。(b) `wait_main_instance_gone` 返回类型改 `()`，`src/update/installer.rs:196`、`:215` 两个返回点改 `return;`，超时与否的行为语义（超时放行交安装器 taskkill 兜底）保留在 doc 注释——行为事实不变，只是不再用返回值表达一个无人读的值。净删约 3 行。(c) 删 `src/update/installer.rs:70`、`:136`、`:162` 的 `.to_uppercase()`。净删 0-1 行（表达式级）。(d) `src/update/version.rs:5` 的 derive 收为 `Debug, PartialEq, PartialOrd`。净删 0 行。评审裁定：(a)(b) 是本笔记的主项；(c)(d) 为 0-1 行收益的表达式级噪声，降为行内 `TODO(update-audit)` 级、不进本次 diff，触碰相邻代码时顺手处理——本笔记只实施 (a)(b)。

## 明确不在本次范围
`UpdateAction` 枚举绝不能删——`src/update/protocol.rs:160` 的 `action == UpdateAction::ExitMain` 转发判定与 `src/update/mod.rs` 里 `complete_update_interaction` 的返回值消费是真实生产语义，本提案只删「记首个」的 memo，不删动作语义本身；`SubprocessOutcome` 与 `ScanOutcome` 不合并——字段搬运冗余仅约 4 行，两层职责（私有扫描细节 vs `pub(super)` 汇报）清晰；`parse_update_action` 的严格协议解析与 `test_scan_invalid_lines_do_not_block_later_exit_main`、`test_scan_dead_target_still_signals_but_not_forwarded` 不动，「跳过无效行」「未送达要上报」是承重性质；(c) 的上游契约（`src/update/crypto.rs:126` 的 `{b:02X}`、`src/update/version.rs:68` 的大写归一）一字不动——本提案删的是下游的第三次归一化，不是契约本身，二者不能一起删。

## 为什么不保留？
(a) 反方：`Option<UpdateAction>` 在调试输出里保留「首个协议动作」的诊断价值，且将来协议若扩为多动作，bool 要回 Option。回应：`ScanOutcome` 不实现 `Debug`（`src/update/protocol.rs:124` 无 derive），诊断价值为零；「多动作协议」目前没有产品归属者，是推测性通用性——真到那天再回 Option 是该付的成本，现在付的是纯表面积。(b) 反方：返回值是「等到了/超时」的语义出口，留着给未来调用方分流。回应：同样属推测性通用性；当下调用点（`src/update/mod.rs:354`）在成功与超时两条路上做同一件事（继续启动安装器，残余进程交 `installer.iss` 的 taskkill 兜底）。(c) 反方：防御性归一化万无一失。回应：「哈希必为大写」的两份上游契约各有测试钉死，第三处归一化是同一事实的第三次表示，且它掩盖契约破坏——上游若哪天返回小写，应由测试先红，而不是靠这里悄悄兜住。(d) 反方：derive 零成本。回应：确实零机器码成本，所以只列为顺带项，不作为立本笔记的理由。

## 风险
(a) 的残余：删掉 `test_scan_memo_keeps_first_action_but_still_forwards` 后，`DONE\nEXIT_MAIN\n` 这类混合输入不再有专属用例——但该用例承载的两条性质分别由更强用例覆盖（「无效行/多行之后仍恰好转发一次」见 `test_scan_invalid_lines_do_not_block_later_exit_main` 与 `test_scan_duplicate_exit_main_forward_only_once`，「DONE 不转发」见 `test_scan_done_does_not_forward`），删除不减保护；证伪方式是把 `scan_subprocess_protocol` 换成「memo 记任意有效动作」的实现，上述用例全绿且对外行为等价——这恰是该测试不承重的证明。(b) 的残余：调用点将来若要区分「等到退出」与「超时」，得把返回值加回来，是真成本但当下无读者。(c)(d) 无行为风险，纯表面积收敛。
