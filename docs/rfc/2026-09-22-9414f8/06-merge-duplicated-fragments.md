# Agent Note：合并 renderer/main/window 六处重复表示与纯转发

Status: proposed

## 问题
三个文件里有六处「同一事实或同一动作的第二份表示」。(1) 箭头字形双表示：`src/renderer.rs:23` 的 `ARROW_UP` 常量（注释 `src/renderer.rs:22` 自述「下行箭头仍走 `Self::wide` 复用 `buf`」）与 `src/renderer.rs:387` 每帧 `Self::wide(&mut self.buf, "\u{2193}")` 并存——↑ 是编译期常量、↓ 每帧 `encode_utf16` 重填，`Self::wide`（`src/renderer.rs:299-303`）全仓唯一调用即此。(2) `update_dpi` 的恒等重设：`src/renderer.rs:495-498` 再次 `SetBkMode(self.hdc_mem, TRANSPARENT)`，而唯一有效设置点是 `Renderer::new` 步骤 8（`src/renderer.rs:263-265`），其间只有 `SelectObject`/`DeleteObject`，背景模式是 DC 属性、不被选入/删除对象重置，此处置的是 `TRANSPARENT → TRANSPARENT` 的空转换；旁证是每帧 `render()` 依赖背景模式跨帧持久却从不重设。(3) `bitmap_size` 回滚块两处逐字重复：`src/main.rs:392-399`（`bind_display_and_timers` 失败分支，理由注释 `src/main.rs:393-394`）与 `src/main.rs:732-740`（`WM_DPICHANGED` 失败分支，注释 `src/main.rs:733-735`）执行同一个「回滚窗口到位图尺寸」动作。(4) `SetWindowLongPtrW` 返回值歧义判别两份：`src/window.rs:231-241`（GWL_STYLE）与 `src/window.rs:242-255`（GWL_EXSTYLE）各写一遍「`SetLastError(0)` → 调用 → `prev == 0 && GetLastError() != 0` → Err」协议（错误点 `src/window.rs:238`、`:252`）。(5) `route_exit_request` 纯转发：`src/main.rs:549-551` 函数体只有一行转发到 `finish_exit_from_watchdog`（`src/main.rs:539`），唯一调用点 `src/main.rs:590`，其文档（`src/main.rs:544-548`）与 `begin_exit`（`src/main.rs:524`）的文档重复同一论证（且自己写着「论证见 begin_exit」）。(6) 边界测试注释的失实半句：`src/renderer.rs:650` 称「改回『先判字节数』或移动闸门阈值即红」，但把闸门 `x >= 10240`（`src/renderer.rs:323-329`）下调到 2048 乃至 11 时现有 8 条断言全绿（逐条手算：1024 → x=10 走 KB 得 "1.0 KB/s"；1048575 → x=10240 仍走 MB 得 "1.0 MB/s"；其余输入本就走 MB），只有上调（≥10241）才变红。检索记录：内置 grep `Self::wide|push_wide|down_arrow|ARROW_UP`（`src/renderer.rs`）命中 8 行、`Self::wide` 唯一调用 `:387`；`SetBkMode`（`src/`）恰 3 处（导入 `src/renderer.rs:9`、`new` `:264`、`update_dpi` `:497`）；`bitmap_size|resize_embedded_window`（`src/`）的消费块恰两处（`src/main.rs:396-397`、`:737-738`）；`route_exit_request|finish_exit_from_watchdog`（`src/`）命中 5 行；`SetWindowLongPtrW|SetLastError`（`src/window.rs`）判别块两份（`:231-255`）。

## 提案
(1) 补 `const ARROW_DOWN: [u16; 2] = [0x2193, 0];` 与 `ARROW_UP` 并排，`src/renderer.rs:387` 改用常量，删 `Self::wide`（`src/renderer.rs:299-303`）与 `push_wide` 导入（`src/renderer.rs:19`，`util::push_wide` 本身另有 `to_wide` 消费、不删），`src/renderer.rs:22` 注释改写为单句双常量说明。注意 `draw_text` 的 `text: &mut [u16]` **不可**收窄为 `&[u16]`：windows-0.62.2 的 safe wrapper 签名是 `pub unsafe fn DrawTextW(hdc: HDC, lpchtext: &mut [u16], lprc: *mut RECT, format: DRAW_TEXT_FORMAT) -> i32`（Windows/Win32/Graphics/Gdi/mod.rs:523），两个箭头各需保留一份 `let mut` 局部拷贝（4 字节栈拷贝）。净删约 4-5 行。(2) 删 `src/renderer.rs:495-498` 的 `SetBkMode` 及其 SAFETY 注释共 4 行。(3) 抽 `fn rollback_window_to_bitmap(hwnd: HWND)`（含单份理由注释），`src/main.rs:392-399` 与 `:732-740` 各收为 1 行调用，`src/main.rs:735` 的「跨屏后的合身位置由下个成功周期自愈」一句留在 `WM_DPICHANGED` 调用点上方。净删约 6 行。(4)（本文实施：降级为行内 `TODO(dedup-setlong)`，判别协议原样保留）判别协议去重记为行内 `TODO(dedup-setlong)`：它落在 AGENTS.md 接缝 1 要求「肉眼可核对」的五步序列里，为 5-7 行牺牲该可核对性不值得；真做时抽模块私有 `unsafe fn set_long_checked` 收口「`SetLastError(0)` → 调用 → `prev == 0 && GetLastError() != 0` → Err」协议、两次调用仍在原位按序内联即可。净删 0 行。(5) 删 `route_exit_request`（`src/main.rs:544-551`），`src/main.rs:590` 改调 `finish_exit_from_watchdog(hwnd)`，其文档中有信息量的一句（「重复请求由幂等门吞掉」）并入 `src/main.rs:587-588` 的臂注释。净删约 8 行。(6) 改写 `src/renderer.rs:647-650` 的失实半句，本文实施补断言方案：新增 1 条把闸门下界钉死的断言 `format_speed_wide(1024 * 1024 - 102) == "1023.9 KB/s"`（净 +1 行，闸门阈值下移即变红，实施时已实测闸门两侧邻居各自裁决）。不提议删除 `test_format_speed_wide_boundaries` 本身——它是 `format_speed_wide` 的唯一覆盖，删除即减保护。

## 明确不在本次范围
`write_u32`（`src/renderer.rs:606-617`）不能删或换 std——它是「渲染热路径零分配」纪律的组成部分（`src/renderer.rs:536` 的 Layout 文档与 `src/util.rs:36` 的 `push_wide` 文档两处成文），换 `to_string()` 会引入每帧 4 次短命堆分配，残余语义不可接受；`watchdog_hwnd` 的 `IsWindow` 预检（`src/window.rs:151-155`）不删——虽然对唯一消费者（`src/update/protocol.rs:203` 的 `post_update_action_to_watchdog`）不改变结果（返回 None 与 PostMessageW 失败汇成同一个 `false`），但删除后契约从「已销毁返回 None」退化为「可能返回陈旧句柄」，安全押在「每个未来调用方都检查投递错误」上，属契约变严的反向成本；`measure_arrow_width`（`src/renderer.rs:576`）的 `to_wide("\u{2191} ")` 是「箭头 + 尾随空格」的测宽串，语义与 (1) 不同，不并入；`EMBEDDED` 的置位/清位点（`src/window.rs:113`、`:208`、`:273`）与嵌入五步顺序（AGENTS.md 接缝 1）一字不动——(4) 只收口第 2、3 步的返回值判别，不改顺序、不改参数、不改失败即 Err 的语义。

## 为什么不保留？
(1) 反方：`src/renderer.rs:22` 注释称刻意为之（复用 `buf`）。回应：常量栈拷贝不分配，还省掉每帧 `encode_utf16`，「复用 buf」的理由对常量不成立；反向合并（删 `ARROW_UP`、两边都走 `Self::wide`）净删更少且保留每帧转码，不是好方向。(2) 反方：防御性重设成本近乎零。回应：恒等重设给出「此处可能被重置」的错误暗示，5 行表面积没有任何行为收益。(3) 反方：两分支注释有细微差异，抽函数后差异要安置。回应：差异句（`src/main.rs:735`）本就属于调用点，主句理由只应有一份。(4) 最强反方：helper 化后 `SetWindowLongPtrW` 不再逐字出现在 `embed_in_taskbar` 正文，AGENTS.md 接缝 1 的「肉眼可核对性」下降。回应：五步顺序与参数逐字不变、两次调用仍在正文按序可见（只是返回值判别的细节进 helper），SAFETY 块同步改写并点名第 2、3 步；若评审认为可核对性权重更高，本项单独降级为一行 `TODO(dedup-setlong)`，其余五项不受影响。(5) 反方：两个名字为消息臂提供「路由语义」锚点，删名损失导航性。回应：实质论证在 `begin_exit`（`src/main.rs:524`）的文档里且 `src/main.rs:546` 已以「论证见 begin_exit」交叉引用，删名不丢论证。(6) 反方：这不是净删型简化。回应：正确，故列为注释纠偏/测试加强二选一，排在本批末位，实施时可只做注释侧。

## 验收标准
`grep -n "Self::wide" src/renderer.rs` 0 命中且 `grep -n "fn wide(" src/renderer.rs` 0 命中（模式须带左括号：测试 helper `fn wide_to_string` 会误命中裸 `fn wide`）；`grep -rn "SetBkMode" src/` 恰 2 处（导入 + `new`）；`grep -n "bitmap_size" src/main.rs` 恰 1 处消费者；`grep -rn "route_exit_request" src/` 0 命中；（(4) 已降为 `TODO(dedup-setlong)`、不设验收项，`prev_style`/`prev_ex` 原样保留）；`cargo test --locked` 全绿，点名 `test_format_speed_wide_boundaries`、`test_write_u32`（`src/renderer.rs`）与 `src/main.rs` 的 5 个用例：`quit_coexists_with_check_update_both_parsed`、`cli_args_require_exact_match`、`cli_args_parses_each_flag_and_ignores_unknown`、`exit_request_gate_accepts_only_first_request`、`stale_main_hwnd_is_rejected`；(6) 若选补断言方案，新断言在闸门下调时必须变红（本次审计已手算验证 2048 与 11 两档下移在旧断言集下全绿）；`cargo build --release --locked` 与 `cargo clippy --all-targets --locked -- -D warnings` 无任何警告。

## 风险
(4) 的残余：若 helper 签名把「STYLE 整体覆盖」与「EXSTYLE 按位或」的差异藏进参数，未来传错不会被编译器拦——缓解是 helper 只收口「返回值判别协议」、两次调用的值表达式仍留在调用点（提案已如此要求）。(6) 的残余：若只改注释不补断言，闸门阈值下移的回归仍无人拦截（如实承认；补断言方案无此残余）。(2) 的残余：若未来 `update_dpi` 改为重建内存 DC（当前无任何此类代码或计划），需把 `SetBkMode` 加回新 DC——证伪依据是 `update_dpi` 的资源替换只涉及位图与字体（`src/renderer.rs:481-492` 两次 `SelectObject`）。(1) 无行为残余（`draw_text` 收窄建议已撤销：windows-0.62.2 的 wrapper 收 `&mut [u16]`，两个箭头各需保留一份 `let mut` 局部拷贝）。(3) 的残余：抽函数后 `WM_DPICHANGED` 分支的额外语义句需留在调用点，review 时须核对注释未随合并丢失。
