# rfc（现行提案）

本目录**只存尚未实施**的 RFC 笔记，是「现在打算改什么」的唯一入口。

**AI 注意**：除本目录的**待办笔记**外，不要读 `docs/` 下任何内容。已实施与历史笔记全部在 `docs/archive/`（默认禁读、可能过时），它们不是现行规范。笔记本身也只在你**动手实施它**时才读，且只读需要的小节。

## 布局：按会话分

```
docs/rfc/
  README.md                       ← 本文件
  <yyyy-mm-dd>-<会话id前6位>/      ← 一次会话的全部产出（只含未完成项）
    01-<topic>.md
    02-<topic>.md
```

- **会话目录**：日期 + 会话 ID 前 6 位，如 `2026-09-10-05939a`。会话 ID 取自环境变量 `$env:DSH_SESSION_ID`（形如 `session-05939a7b-3169-…`，取 `session-` 之后的 6 位）；取不到时用简短的 kebab-case 主题词兜底（如 `2026-09-10-migration`）。一个会话目录可含多篇互不相关的笔记。
- **文件名**：`NN-<topic>.md`，`NN` 为两位序号，`topic` 用 kebab-case 英文、动作导向。
- **已实施**的笔记移出本目录，落到 `docs/archive/rfc/<同一会话目录>/`，状态行改为 `implemented`。因此 `docs/rfc/<会话>/` 天然只含未完成项、`docs/rfc/` 下没有历史积累。

## 状态语义

状态行是「是否完成」的唯一真值，写在标题后一行：

    Status: proposed      ← 未实施，待办清单
    Status: implemented   ← 已实施，且用户已确认功能可用

（上面是**缩进的示例文本**，故意不写成行首，以免被下面的查询误命中。）

- 查待办：`grep -rn "^Status: *proposed" docs/rfc/`。**只认 `docs/rfc/<会话目录>/NN-*.md` 的命中**；本 README 里的示例不是待办。
- `implemented` 的写入有硬性前置条件：必须等用户明确确认功能可用，CI 绿不算。
- 标记完成时**只改这一行**，并同时把文件移入 `docs/archive/rfc/<会话目录>/`。两件事一起做，不存在「代码已合并、规范仍写在待办目录」的中间态。
- **不写入日期或提交 SHA**：它们只存在于 git 历史，rebase 后会失真。

## 笔记结构与写作要求

```markdown
# Agent Note：<动作导向的中文标题>

## 问题
## 提案
## 明确不在本次范围      ← 可选，强烈建议
## 为什么不保留？
## 验收标准
## 风险
```

- 正文段落写成**单个物理行**，不为排版硬折行。
- 证据具体到 `file:line`，说明做过什么检索、命中几处。**不要拿「某篇历史笔记写过」当证据**——依据当前 code。
- 区分**生产消费者**与**非生产消费者**（测试 / 文档 / 注释），两者都要列。
- 「明确不在本次范围」要写清相邻项为何**不能**一起删——这条专门用来挡住未来「顺手一起删」的误改。
- 「为什么不保留？」要写出最强的反方理由并逐条回应，不要自我吹捧。
- 「验收标准」要可 grep、可执行；行为一致性用现有测试名点名。
- 「风险」必须承认真实残留风险；能证伪的风险就写明证伪依据。
- 相对链接指向仓库源码：`docs/rfc/<会话>/` 下是 `../../../src/...`；移入 `docs/archive/rfc/<会话>/` 后多一层，变 `../../../../src/...`。
